## Scope and evidence

Hub ingestion/history/realtime repositories, Go collection/backend scheduling, Android
release configuration and release/CI packaging. The legacy WinUI host and iOS are not
the active Windows distribution. This is a source-path audit plus controlled Actions
measurements, not a claim that every device or production workload has been profiled.

## Quantifiable expectations, not measured claims

At a five-second UI refresh cadence, ignoring request duration:

- Hidden scheduled UI refreshes: up to 12/minute → 0 after in-flight work completes.
- Cache disk reads: up to 12/minute → once per process (hot reads reuse memory).
- Cache writes: up to 12/minute → at most one/minute during polling, plus exit flush.
- Successful desktop update queries: up to 180/15 minutes → 1 per Hub/version.
- Post-inventory network critical path: sum of optional request durations → maximum
  duration (backend contention may reduce the gain; no predicted millisecond claim).
- Repeated profile calls within 30 seconds: N blocking process launches → at most
  one asynchronous process launch. Memory pressure is still sampled on each call.
- Web ordinary telemetry push: up to five follow-up HTTP calls → zero; existing
  visible UI poll remains the source of history refreshes.

## Other findings and decisions

- Chromium/Node runtime is the dominant fixed cost for this Electron distribution.
  `spellcheck:false`, a single BrowserWindow, default background throttling and bounded
  recovery loops already exist. Removing GPU support, locale files or switching hosts
  would require compatibility evidence; do not claim generic WebView2 memory savings.
- Agent uses separate normal/slow sampling and a cached hardware sensor helper. These
  perform actual monitoring. Do not disable them to make a GUI-only benchmark look
  cheaper. Hardware/WMI subprocess and service memory require a physical Windows
  workload with the user's enabled probes; NOT MEASURED by the fixture benchmark.
- Hub historical calendar reads retain up to minute/hour retention windows and full
  JSON detail columns; `listKnownDevices` unions history; overview fans out across
  devices. These are plausible high-cost production paths, but row counts, EXPLAIN,
  query latency and DB load are unavailable here. Next step: controlled large-history
  benchmark before changing retention, indexes or aggregation semantics.
- Metrics accumulators cap samples; offline cleanup exists. No demonstrated leak was
  established. Web summary arrays/context still invalidate consumers per push; split
  context or virtualize lists only after large-inventory render profiling.
- Android release disables R8 minification, and the APK is about 50 MiB. Enabling R8
  without release-variant serialization/Retrofit/Compose and device acceptance risks
  runtime breakage. Record as a follow-up, not a silently enabled size-only change.
- Diagnostic synchronous file operations are rare and bounded to a 2 MiB log. Leave
  crash evidence reliability intact instead of introducing a broad logging rewrite.

## Verification protocol

`ci.yml` and `release-test.yml` run existing type/build/platform tests plus
`scripts/performance-regression.test.mjs` (cache I/O, visibility lifecycle, async probe,
request parallelism, update caching and authentication deduplication). Existing release
checks exercise Windows install/reinstall, packaged navigation, headless service,
Linux install/uninstall and Android tests/lint/build.

`performance-audit.yml` downloads checksum-verified baseline/candidate portable
Release assets on the same Windows runner. It alternates three launches per version,
uses fresh app data, measures package/ASAR/category bytes, time to visible overview,
20 runtime-profile IPC calls, initial JS resources, renderer heap, and all Electron
process CPU/working-set samples while visible and hidden. Stores raw JSON artifact.
No timing thresholds hide noise; ASAR duplicate-dependency/maps checks are hard gates.
OS cache is warm. Fixture GUI measurements exclude real Hub, Agent and sensor costs;
working-set sums can double-count shared pages. They are not physical-device E2E.

Current workstation is Linux (`ubuntu-dev`), without a local Windows PowerShell/WSL
bridge. Required local Windows setup installation is BLOCKED; Windows-runner install
success cannot substitute for it. Download/hash verification can still be completed.
