# Performance results — v3.0.27 → v3.0.28

The performance implementation is `8148271`, with the test harness resolution fix
in `106cd39`. Both are on main and included in prerelease v3.0.28. The independent
v3.0.29 asset-name migration also contains these optimizations; its performance
has not been separately benchmarked. No production deployment or latest update.

## Measurements

passed. Download its `desktop-performance-comparison` artifact for raw JSON.

was not cleared. Values below are decimal MB or explicitly binary MiB.

Startup samples before: 1964/773/755 ms; after: 631/573/609 ms. The baseline
first launch is an outlier, so use the median and do not claim cold-start gains.
CPU/working-set values aggregate 30 one-second samples per phase/version.
Process working sets can double-count shared pages. `performance.memory` is
coarse and GC-sensitive; its increase is retained rather than hidden. Longer
heap/allocation traces under a real workload are required to explain it.
Resource Timing returned an empty initial-JS list for packaged file:// pages;
therefore initial-JS reduction is build-graph evidence, not a measured network
transfer metric. ASAR asserts confirm no duplicate npm payload/maps remain.

## Remaining audit priorities

1. Profile Hub historical calendar row/JSON volume, overview fan-out and Redis
   `appendSeries` LRANGE/parse/rewrite cost (up to 150 existing points per append).
   Retain duplicate-timestamp correction and ordering if replacing with Lua or
   a different structure; require integration coverage against real Redis/DB.
2. Both Dockerfiles are single-stage and retain build tools/source. A filtered
   multi-stage production image could yield substantial savings, but needs
   standalone runtime, migrations, configuration and deployment smoke coverage.
3. Android disables release R8; evaluate with release-variant reflection,
   serialization, signing and device acceptance before enabling shrinking.
4. iOS schedules a five-second timer that spawns Tasks; slow requests could
   overlap. No iOS workflow/device is available for acceptance. Legacy WinUI
   also has polling loops, but is not the shipped Electron host. Do not delete
   legacy code simply to claim package savings: it is already outside ASAR.
5. Native sensor/WMI cost and large-inventory renderer/context invalidation
   need real workload profiles. CPU improvement remains unproven beyond avoided
   scheduled/request work and eliminated synchronous query.exe calls.

The crash-cache freshness tradeoff and Web history-refresh cadence change are
explicitly documented in the audit and release notes. See
[the audit](2026-09-19-audit.md) for scope and source paths.
