# Android 前端重构：读数优先（2026-10）

优先级：**数据可读性 > 上手难度 > 美观 > 操作顺手**。视觉重心放在图表；异常设备与需要关注的问题排第二。
设计系统仍是 `ui/oneui`（见 `ONE_UI_DESIGN_SYSTEM.md`），本次只改信息架构、图表与读数口径，不换体系。

## 信息架构

| 一级目的地 | 内容 |
| --- | --- |
| 总览 | 关注汇总条（一行）+ 每台设备一张趋势卡（CPU / 内存 / 网络迷你曲线 + 硬盘容量条） |
| 关注 | 所有设备的问题按 严重 → 警告 → 离线 排列，点一行直达对应类别；导航徽标只数严重 + 警告 |
| 设置 | 不变 |

设备页分四个标签：**概览**（核心图表常驻）、**硬件**（类别列表 → 实例明细）、**进程**、**容器**。
时间范围（实时 / 5 分钟 / 1 小时 / 6 小时 / 24 小时 / 7 天）吸附在标签下方；「1 分钟」被「实时」取代。
流量日历仍是独立页，入口在概览底部（它自带日历与周期切换坞，塞进标签页反而难用）。
顶栏「⇄」切换设备时保留当前标签，方便对比两台机器的同一类数据。

## 读数口径

- 标题位大数字一律是**当前值**（时间上最新的样本），旁边写明口径；图下统计行给出所选范围内的**均值与峰值**。
  旧版在 1 分钟以外取区间均值做大数字，会把尖峰抹平，且同一张卡里大数字、游标、内存字节数三种口径混用。
- 颜色只在越过阈值时出现（警告 / 临界色），平时中性。
- 成对指标同图：接收/发送、读取/写入、物理/Swap、占用/显存、CPU/显卡温度。成对序列固定用蓝（0）与青（2），避开像告警色的橙红。

## 图表（`OneUiCharts.kt`）

- 纵轴整齐刻度（1/2/2.5/5×10ⁿ，`niceAxis`），横轴起点 / 中点 / 终点时间。
- 阈值虚线：离数据不远（≤ 数据最大值 × 1.35）时撑开坐标轴画出来，太远则不画，避免把曲线压平。
- 只响应点按与**横向**拖动；竖向滑动交给列表（旧版 `detectDragGestures` 会吃掉竖向手势，图表多的页面划不动）。双击回到最新。
- 修复：旧版横轴时间把毫秒数当 ISO 字符串解析，起止标签永远显示「--」。

## 关注规则（`attention.kt`，纯函数）

中枢不下发告警，规则在客户端判定，只比较当前值：

| 规则 | 警告 | 严重 |
| --- | --- | --- |
| CPU 占用 | ≥ 85% | ≥ 95% |
| 内存占用 | ≥ 88% | ≥ 95% |
| 硬盘 / 存储池占用 | ≥ 85% | ≥ 95% |
| 精简池元数据 | ≥ 80% | ≥ 90% |
| Swap 占用 | ≥ 80% | — |
| GPU 内存 | ≥ 95% | — |
| 温度（传感器自报阈值优先，合理范围 30–150 °C） | CPU 85 / 显卡 83 / 硬盘 55 °C | CPU 95 / 显卡 90 / 硬盘 65 °C |
| 硬盘 SMART | caution | bad，或寿命 ≤ 10% |
| 上报中断（在线但 3 分钟无新上报） | ✓ | — |

摘要层规则每 15 秒随设备列表刷新；温度、硬盘健康、存储池需要各设备指标快照，每分钟后台并发拉一次（5 分钟粒度），进入关注页或手动刷新时立即拉一次。

## 实时查看（`live.kt` + `LiveScreens.kt`）

接口：`GET /api/devices/:id/live`、`GET /api/devices/:id/live/{metrics|processes|docker}`、`POST /api/devices/:id/live/reset`。
语义与 Web / 桌面端 `livePresentation.ts` 一致：

- 只在对应内容可见、应用在前台时轮询；离开页面、进后台、暂停都**不发请求**。默认曲线 1 秒、进程 / 容器 2 秒。
- 超过 max(6 秒, 两个刷新周期) 未确认的结果视为过期，不再称为「实时」；设备繁忙、超时等一过性失败保留上次结果并标注，其它失败立即清空。
- 每种失败都有一句「它意味着什么、不意味着什么」（例如没有 Docker 读取权限 ≠ 没有容器）。
- 进程：读不到的值（—）无论升降序都排在最后；展开某一行时保持行序，重排最多每 5 秒一次；GPU 列只在设备提供进程 GPU 数据时出现。
- 安装身份冲突时给出「重置实时凭据」入口，二次确认后执行。
